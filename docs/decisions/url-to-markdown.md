# URL to Markdown 변환과 LLM 넘기기

## Decisions

- 변환은 서버에서 합니다. 서버가 URL을 `fetch`해 HTML을 받고, `linkedom`으로 만든 DOM을 `Defuddle(document, url, { markdown: true })`에 넘깁니다. defuddle은 URL 문자열이 아니라 DOM을 받습니다.
- 저자(`author`)는 비어 있을 수 있다고 전제합니다. 비면 헤더에서 저자 자리를 생략합니다.
- HTML이 아닌 응답이나 빈 본문은 오류로 처리하고 결과 영역을 만들지 않습니다. defuddle이 HTML이 아닌 응답에서 예외를 던집니다.
- ChatGPT·Claude로 열기는 항상 `프롬프트 + 빈 줄 + 본문`을 먼저 클립보드에 복사합니다. URL 인코딩 후 6,000자 이하일 때만 `?q=`로 입력창을 채우고, 넘으면 서비스만 열고 "붙여넣기 하세요" 안내를 보여줍니다.
- 프롬프트는 ChatGPT·Claude로 열기에만 붙입니다. 복사하기와 `.md` 다운로드는 항상 본문만 다룹니다.
- 결과 카드는 제목 헤더, 내보내기 영역, 본문 순서로 두고, 본문은 카드 안에서 따로 스크롤하지 않습니다.

## Boundaries

- 6,000자 기준은 검증한 값이 아니라 안전하게 잡은 시작값입니다. 한글은 인코딩하면 글자당 약 5.5자로 늘어나 한글 본문 약 1,100자만 넘어도 안내 경로를 탑니다. 한국어 기사 대부분은 클립보드 경로가 기본 동작입니다.
- 서버 측 보안 하드닝(내부망 주소 차단, 요청 한도)은 학습용 템플릿 예산에 따라 범위 밖입니다. 서버가 임의의 URL을 가져온다는 점은 알려진 위험입니다.
- 로그인이 필요한 페이지, 유료 벽, JavaScript로 그리는 사이트는 처리하지 않습니다. 본문이 비면 오류가 됩니다.

## Why

브라우저에서는 대상 사이트의 CORS 때문에 HTML을 가져올 수 없어서 서버 변환이 필요합니다.

`chatgpt.com/?q=`는 32,000자까지 200, 64,000자에서 431이었지만, 한글은 인코딩하면 길이가 크게 늘어 일반 기사는 URL에 담기지 않습니다. 그래서 어떤 경우에도 사용자가 본문을 LLM에 넣을 수 있도록 클립보드 복사를 기본 경로로 둡니다.

## Reconsider when

- `claude.ai/new?q=`가 로그인 상태에서 입력창을 실제로 채우는지, 허용 길이가 얼마인지 확인되면 6,000자 기준을 조정합니다. curl은 Cloudflare 403을 받아 확인하지 못했고, 브라우저로 확인해야 합니다.

## Still-rejected alternatives

- 내보내기 영역을 하단 고정 바로 두는 방식 — 어디서나 내보낼 수 있지만 모바일 화면 높이의 약 15%를 차지하고, 안내 문구가 뜨면 바가 커집니다.
- 내보내기 영역을 본문 아래에 두는 방식 — 긴 기사에서 카드 안 스크롤이 생깁니다.
- `?q=`만으로 넘기는 방식 — 한글 본문은 대부분 길이 한도를 넘어 본문이 전달되지 않습니다.

## Evidence worth preserving

- defuddle 0.19.6과 `linkedom`으로 Wikipedia, Next.js 블로그, Hacker News, X 게시물의 title, site, Markdown 추출을 확인했습니다. 이 중 Next.js 블로그, 예시 도메인, Hacker News는 저자가 비었습니다.

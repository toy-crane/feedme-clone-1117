# 저장한 글: 변환 결과를 저장하고 목록에서 다시 보기

Related decisions: [docs/decisions/url-to-markdown.md](../../decisions/url-to-markdown.md) — 복사, `.md` 다운로드, ChatGPT·Claude로 열기의 동작과 프롬프트 규칙을 저장한 글 화면에서도 그대로 따른다.
Related decisions: [docs/decisions/ui-composition.md](../../decisions/ui-composition.md) — 목록, 빈 상태, 로딩, 오류 상태를 shadcn 구성과 semantic token으로 만든다.
Terms: [GLOSSARY.md](../../../GLOSSARY.md) — 변환, 저장한 글, 저장 목록.

## 사용자에게 달라지는 것

- 변환 결과 카드에서 "저장"으로 그 결과를 내 **저장한 글**로 남길 수 있다.
- 새로고침하거나 다른 날 와도 **저장 목록**(`/saved`)에서 저장한 글을 다시 열어 볼 수 있다.
- 저장한 글 화면에서 복사, `.md` 다운로드, ChatGPT·Claude로 열기를 변환 직후와 똑같이 쓴다.

## 범위

- 저장: 로그인한 사용자가 변환 결과 카드에서 저장한다. 저장하는 값은 제목, 저자, 사이트, 원문 URL, Markdown 본문이다.
- 저장 목록: 로그인한 사용자 본인의 저장한 글을 저장일 최신순으로 보여 준다. 각 항목은 제목, 사이트, 저장일을 보인다.
- 저장한 글 보기: 목록 항목을 누르면 저장된 본문을 보여 준다. 헤더에 제목, 저자(있으면), 사이트, 원문 링크를 둔다.
- 진입점: 로그인 상태의 홈 헤더에서 저장 목록으로 갈 수 있다.

## 수용 기준

1. 로그인한 사용자가 변환 후 "저장"을 누르면 저장되었다는 표시가 보이고, 같은 카드에서 버튼이 "저장됨" 상태가 된다.
2. 저장 후 `/saved`를 열면 방금 저장한 글이 목록 맨 위에 제목, 사이트, 저장일과 함께 보인다.
3. 새로고침하거나 로그아웃 후 다시 로그인해도 저장한 글이 그대로 있다.
4. 목록 항목을 누르면 저장 당시의 본문이 보이고, 복사, `.md` 다운로드, ChatGPT·Claude로 열기가 `url-to-markdown` 계약대로 동작한다.
5. 같은 사용자가 같은 URL을 다시 저장하면 새 항목이 생기지 않고, 기존 저장한 글이 최신 변환 결과와 새 저장일로 덮어써진다. 목록에는 그 글이 한 번만 보이고 맨 위로 올라온다.
6. 이미 저장된 URL을 변환하면 결과 카드의 버튼이 "저장됨"으로 보이고, 다시 눌러 갱신할 수 있다.
7. 비로그인 사용자가 "저장"을 누르면 로그인 페이지로 이동하고, 로그인하면 홈으로 돌아온다. 이때 이전 변환 결과는 사라져 다시 변환해야 한다.
8. 비로그인 사용자가 `/saved`로 가면 로그인 페이지로 이동하고, 로그인 후 `/saved`로 돌아온다.
9. 사용자 A의 저장한 글은 사용자 B가 목록과 직접 주소 어느 쪽으로도 볼 수 없다. 남의 글 주소는 "찾을 수 없음"으로 처리한다.
10. 저장한 글이 없으면 빈 상태 안내와 홈으로 가는 동선을 보여 준다. 목록 로딩 중에는 skeleton, 저장 실패 시에는 오류 안내를 보인다.

## 확정한 제약과 이유

- 저장한 글은 스냅샷이다. 원문 URL을 다시 받아 갱신하지 않는다. 저장본이 원문 변경이나 삭제에 영향받지 않아야 "다시 볼 수 있다"는 약속이 지켜진다.
- 한 사용자당 같은 원문 URL은 하나만 둔다(사용자 선택). 같은 글이 목록에 여러 번 쌓이지 않고, 원문이 갱신되었을 때 최신본으로 바꿀 수 있다.
- 저장과 조회는 소유자만 가능하다. 기존 `profiles`의 로그인 방식과 owner-only 접근 규칙을 따른다.
- 저장은 로그인 필수다. 비로그인 임시 저장은 두지 않는다.

## 가정 (에이전트가 정함, 바꿔도 되는 값)

- 비로그인 사용자의 저장 시도는 결과를 보존하지 않고 로그인으로 보낸다. 되돌아와 다시 변환하는 비용이 작다고 본다.
- URL 비교는 `new URL(...).href`로 정규화한 값 기준이다. 추적 파라미터 제거 같은 추가 정규화는 하지 않는다.
- 목록은 한 번에 전부 보여 준다(페이지네이션 없음).

## 범위 밖

- 삭제, 편집, 검색, 태그, 폴더, 공유: 이번 요청에 없다.
- 서버 측 보안 하드닝과 성능 방어: 학습용 템플릿 예산에 따라 범위 밖이다.

## 보류한 결정

- 저장한 글 삭제: 요청 범위 밖이라 뺐다. 목록이 쌓여 불편하다는 사용 경험이 생기면 다시 연다. 그때까지 사용자는 저장한 글을 지울 수 없다(임시 동작).
- 비로그인 사용자의 변환 결과 보존: 로그인 왕복 후 결과가 사라지는 불편이 실제로 문제가 되면 다시 연다.

## 남은 위험

- 한 글의 Markdown이 매우 크면 저장과 목록 응답이 느릴 수 있다. 목록이 본문 없이 제목, 사이트, 저장일만 읽는 것은 구현에서 판단한다.
- 삭제가 없어서 잘못 저장한 글이 남는다.

# URL을 Markdown으로 변환해 LLM으로 넘기기

웹 페이지 URL을 붙여넣으면 본문만 Markdown으로 뽑아 보여주고, 복사하거나 `.md`로 받거나 ChatGPT·Claude에 바로 넘길 수 있는 서비스입니다. 계정, 저장, 서버 DB는 없습니다.

Blocked by: 없음

## 연결된 소스

- `docs/decisions/ui-composition.md`: 화면 구성(shadcn 기본, semantic token, 상태 설계, 반응형)을 따릅니다. 이 스펙은 그 규칙을 다시 적지 않습니다.
- `docs/decisions/dependency-versions.md`: 새 의존성을 추가할 때의 버전 정책입니다.
- `docs/specs/url-to-markdown/prototype.html`: 승인된 화면과 상태(입력, 변환 중, 결과, 저자 없는 결과, 오류, 다크모드, 390px 폭)의 기준입니다. 화면 구성과 위치는 이 파일을 따르고, 동작 규칙은 이 스펙의 인수 기준을 따릅니다. 프로토타입의 "열기"는 새 탭을 열지 않고 안내 문구만 보여 주며, 변환 결과는 더미 데이터입니다.

## 사용자에게 보이는 결과

한 페이지짜리 서비스입니다. 결과 카드는 위에서 아래로 제목 헤더, 내보내기 영역(프롬프트 선택과 버튼), 렌더링된 본문 순서로 놓입니다. 본문은 카드 안에서 따로 스크롤하지 않고 페이지 흐름대로 길어집니다. 사용자는 아래 순서로 씁니다.

1. **입력**: URL을 붙여넣고 변환합니다. 지우기 버튼을 누르면 입력과 결과가 모두 처음 상태로 돌아갑니다.
2. **변환**: 페이지 본문만 Markdown으로 추출합니다. 광고, 내비게이션 같은 주변 요소는 빠집니다.
3. **결과 확인**: 페이지 제목과 저자가 있는 헤더, 그 아래에 렌더링된 Markdown이 나옵니다.
4. **내보내기**
   - 복사하기: Markdown 본문을 클립보드에 복사합니다.
   - `.md` 다운로드: Markdown 본문을 파일로 저장합니다.
   - ChatGPT로 열기 / Claude로 열기: 선택한 프롬프트를 본문 앞에 붙여 해당 서비스로 넘깁니다.
5. **프롬프트(선택)**: 프롬프트 없음(기본), 요약해줘, 한국어로 번역해줘, 쉽게 설명해줘, 직접 입력 중에서 고릅니다. "직접 입력"을 고르면 텍스트 입력칸이 나타납니다. 직접 입력한 문장은 저장하지 않고, 새로고침하거나 지우기를 누르면 사라집니다.
6. **다크모드 토글**: 라이트와 다크를 직접 바꿀 수 있습니다.

## 승인된 범위

- 위 사용자 흐름 전체를 하나의 페이지로 구현합니다. 기존 홈의 시작용 안내 화면은 이 서비스로 대체됩니다.
- 본문 추출은 defuddle 라이브러리를 사용합니다(필수).
- 화면 문구는 한국어입니다.

## 인수 기준

1. 기사 형태의 공개 URL(예: Wikipedia 문서)을 입력하면 로딩 표시 뒤에 제목 헤더와 렌더링된 Markdown 본문이 나온다. 본문에는 제목, 문단, 링크, 목록이 Markdown 요소로 표시된다.
2. 저자 정보가 있는 페이지는 헤더에 저자가 보이고, 저자 정보가 없는 페이지는 저자 자리가 비어 보이지 않게 생략된다.
3. 지우기 버튼은 URL 입력, 결과, 오류 메시지, 프롬프트 선택, 직접 입력 문장을 모두 초기화한다.
4. 복사하기를 누르면 클립보드에 Markdown 본문만 들어가고, 복사됐다는 피드백이 보인다. 프롬프트는 붙지 않는다.
5. `.md` 다운로드는 Markdown 본문만 담은 파일을 저장한다. 파일명은 페이지 제목에서 만들고, 제목이 비면 `page.md`를 쓴다.
6. 프리셋(또는 직접 입력)을 고른 상태에서 ChatGPT로 열기 또는 Claude로 열기를 누르면, `프롬프트 + 빈 줄 + 본문`이 먼저 클립보드에 복사되고 해당 서비스가 새 탭으로 열린다. 프롬프트 없음이면 본문만 복사된다.
7. 6번에서 (프롬프트 + 본문)을 URL 인코딩한 길이가 6,000자 이하이면 `?q=`로 입력창을 바로 채운다. 이보다 길면 `?q=` 없이 서비스만 열고, 화면에 "클립보드에 복사했습니다. 붙여넣기 하세요" 안내를 보여준다.
8. "직접 입력"을 고르면 텍스트 입력칸이 나타나고, 다른 선택지로 바꾸면 사라진다. 입력한 문장은 새로고침 뒤에 남아 있지 않다.
9. 직접 입력을 골랐는데 입력칸이 비어 있으면 프롬프트 없음처럼 동작한다.
10. 다음 입력은 오류 메시지를 보여주고 결과 영역을 만들지 않는다. 오류 뒤에도 입력창은 그대로 쓸 수 있다.
    - URL 형식이 아니거나 `http`, `https`가 아닌 주소
    - 페이지를 가져오지 못하는 경우(접속 실패, 4xx/5xx)
    - HTML이 아닌 응답이거나 추출된 본문이 비어 있는 경우
11. 다크모드 토글을 누르면 전체 화면(렌더링된 Markdown 포함)이 라이트와 다크로 바뀐다. 최초에는 OS 설정을 따르고, 한 번 고른 뒤에는 새로고침해도 유지된다.
12. 결과 카드는 제목 헤더, 내보내기 영역, 본문 순서로 놓이고, 본문은 카드 안 스크롤 없이 페이지와 함께 스크롤된다. 본문이 길어도 내보내기 영역은 헤더 바로 아래에 있다.
13. 좁은 화면(모바일 폭)에서도 입력, 결과, 내보내기 버튼, 프롬프트 선택이 가로 스크롤 없이 모두 사용 가능하다.

## 확정된 제약과 근거

- **내보내기 영역은 결과 카드의 제목 헤더 바로 아래, 본문 위에 둔다(사용자가 선택한 C안).** 하단 고정 바(B)와 본문 아래 배치(A)를 같은 기사와 390px 폭에서 비교했다. B는 어디서나 내보낼 수 있지만 모바일 화면 높이의 약 15%를 차지하고 안내 문구가 뜨면 바가 커진다. A는 긴 기사에서 카드 안 스크롤이 생긴다. C는 변환 직후 바로 내보낼 수 있고 안내 문구가 본문을 가리지 않는다. 그 대가로 결과를 읽기 전에 프롬프트 선택이 먼저 보인다.

- **변환은 서버에서 한다.** 브라우저에서는 대상 사이트의 CORS 때문에 HTML을 가져올 수 없다. defuddle은 Node에서 사용하려면 DOM 구현체가 필요하고, URL 문자열이 아니라 가져온 HTML의 DOM을 받는다. scratch에서 defuddle 0.19.6과 `linkedom`으로 Wikipedia, Next.js 블로그, Hacker News, X 게시물의 title, site, Markdown 추출을 확인했다. 확인 방법은 HTML을 `fetch`한 뒤 `Defuddle(document, url, { markdown: true })`를 호출하는 것이었다.
- **`author`는 자주 비어 있다.** 같은 확인에서 Next.js 블로그, 예시 도메인, Hacker News는 저자가 비었다. 그래서 인수 기준 2번이 필요하다.
- **HTML이 아닌 응답은 defuddle이 예외를 던진다.** 빈 본문 응답에서 확인했다. 그래서 인수 기준 10번의 오류 상태가 필요하다.
- **ChatGPT·Claude로 열기는 항상 클립보드를 거친다(사용자가 선택한 방식 A).** `chatgpt.com/?q=`는 scratch에서 32,000자까지 200, 64,000자에서 431이었다. 한글은 인코딩하면 길이가 크게 늘어나 일반 기사는 URL에 담기지 않는다. 어떤 경우에도 사용자가 본문을 LLM에 넣을 수 있게 하려고 클립보드 복사를 기본 경로로 둔다. 6,000자 기준은 안전한 값으로 정한 시작값이며, 근거가 아니라 가정이다(아래 가정 참고).
- 프롬프트는 ChatGPT·Claude로 열기에만 적용한다. 복사하기와 `.md` 다운로드는 항상 본문만 다룬다.
- 화면은 `ui-composition` 계약(shadcn, semantic token, loading/error/empty 상태 설계)을 따른다. 다크모드도 semantic token으로 표현한다.

## 가정(덮어쓸 수 있음)

- 변환은 URL 입력 후 Enter 또는 변환 버튼으로 시작한다. 붙여넣기만으로 자동 변환하지 않는다.
- 6,000자(URL 인코딩 후)를 `?q=` 사용 기준으로 둔다. 서비스별로 더 크게 허용될 수 있지만 확인하지 못했다. 한글은 인코딩하면 글자당 약 5.5자로 늘어나(프로토타입 샘플은 1,309자가 7,282자), 한글 본문은 약 1,100자만 넘어도 "붙여넣기 하세요" 안내 경로를 탄다. 그래서 한국어 기사 대부분은 이 경로가 기본 동작이 된다. 이 값을 바꾸고 싶다면 이 가정을 덮어쓴다.
- 지우기는 프롬프트 선택까지 초기화한다.
- 렌더링된 Markdown은 읽기 전용이다. 본문 편집 기능은 없다.
- 다크모드 선택은 이 브라우저에만 저장한다.
- 서비스 도메인이 아닌 별도 접근 제한(로그인이 필요한 페이지, 유료 벽)은 처리하지 않는다. 가져오지 못하면 인수 기준 10번의 오류가 된다.
- `add-stack-context`는 호출하지 않았다. defuddle은 프레임워크나 호스팅 서비스가 아닌 라이브러리이고, 프로젝트의 기존 스택(Next.js, shadcn)은 이 결정으로 바뀌지 않는다.

## 범위 밖

- 계정, 로그인, 변환 기록, 즐겨찾기, 서버 저장. 저장이 필요 없다는 사용자 흐름에 따른다.
- 직접 입력 프롬프트의 저장, 프롬프트 프리셋 편집. 1회용으로 정했다.
- Markdown 외 출력 형식(HTML, PDF).
- 여러 URL 일괄 변환.
- 서버 측 보안 하드닝(내부망 주소 차단, 요청 한도 등). 스펙이 요구하지 않았고 학습용 템플릿이라는 프로젝트 예산에 따라 범위 밖이다. 아래 위험에 적는다.

## 남은 위험

- `claude.ai/new?q=`가 로그인 상태에서 입력창을 실제로 채우는지, 허용 길이가 얼마인지 확인하지 못했다(curl이 Cloudflare 403을 받음). 동작하지 않아도 클립보드 복사가 있으므로 사용자는 붙여넣기로 진행할 수 있다. 구현 중 런타임 검증에서 확인하고, 다르면 7번의 기준을 조정한다.
- 서버가 사용자가 준 임의의 URL을 가져오므로, 내부망 주소 요청 같은 남용 가능성이 있다. 범위 밖으로 정했다.
- 변환된 Markdown에 원본 페이지의 HTML이 섞여 있을 수 있다. 렌더링 때 스크립트가 실행되지 않게 하는 것은 구현에서 기본값 수준으로만 다룬다.
- JavaScript로 그리는 사이트는 서버 `fetch`로 본문이 비어 있을 수 있다. 이 경우 인수 기준 10번의 빈 본문 오류가 된다.
